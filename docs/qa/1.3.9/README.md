후속 공개 배포: 사용자 요청으로 검증한 1.3.9와 1.3.8 누적 수정을 정식 릴리스·main·Pages에 반영합니다. 아래 원격 미반영 문장은 감사 완료 당시 범위입니다. 기존 사용자 설치는 이번 공개 배포에서도 변경하지 않습니다.

## 환경과 증거 기준

- 실제 **macOS 27.2 (26B123), Obsidian 1.15.0**. 보관함은 기존 `MIA-Final-UI-Audit` 하나만 사용했습니다. 새 QA 앱·보관함·프로필·진단 플러그인을 만들지 않았습니다.
- 기존 테스트 보관함 전체를 백업하고 이전 `MIA/` 문제 자료를 백업 경로로 옮겨 **등록 문제 0개**로 시작했습니다. 이전 테스트 설정·충돌 사본·과거 이력은 보존했으므로 완전히 초기화한 최초 설치 환경은 아닙니다.
- 과목 생성, 첫 6문제 등록, 검색·필터, 설정 오류 교정, 네 평가 버튼, 긴 답변 편집과 창 크기 변경은 native 접근성·마우스·키보드로 조작했습니다.
- 이후 반복 작업은 **같은 실제 Obsidian renderer의 DevTools에서 실제 DOM 입력·버튼·모달 이벤트**로 실행했습니다. MIA의 평가·출제·편집 함수를 직접 호출해 사용자 흐름을 대신하지 않았습니다. 화면은 native 캡처와 실제 Electron 창 `capturePage()`로 남겼습니다. 브라우저 모의·시뮬레이터가 아닙니다.
- 내부 API는 읽기 대조, 표시한 기한 도래 자료 준비, 한 번의 저장/인덱스 실패 주입, Obsidian의 플러그인 관리에만 별도로 사용했습니다. 실패 주입은 실제 디스크 고장·클라우드 장애를 뜻하지 않습니다.
- 최종 main.js SHA-256: `d75d4dc96feb8d0405c2a987b03ae28553331659bcc7fde1168b812f1285268e`. CSS·manifest 포함 세 파일이 격리 설치와 바이트 동일합니다. 정확한 지문은 구조화 요약에 있습니다.

## 발견한 제품 결함과 수정

**저장 실패 복구 뒤 완료 화면에서 평가 집계 누락**

1. 시험의 마지막 복습 문제에 ‘암기’를 누르고 primary 저장이 한 번 실패하게 합니다.
2. 대시보드 → 미완료 저장 확인 → 최신 파일과 확인 후 저장 재시도 → 이어하기.
3. 기대: 저장된 평가를 다시 수행하지 않고 완료 집계에도 암기 1을 표시해야 합니다.
4. 1.3.8 실제 결과: 해당 ID의 이력과 예약은 정상 저장됐지만 완료 화면의 암기는 0이었습니다. 원본 증거 `62-before-review-failure-data.json`, `63-*`, `64-*`, `65-*`, **`66-resume-after-recovery-dom.json`**.
5. 원인: [study-view.ts](../../../src/ui/study-view.ts)의 `restoredQueueIndex`가 checkpoint와 저장된 버전 차이를 보고 위치만 전진시켰고 세션 결과 map을 복원하지 않았습니다. workspace 복원도 같은 경계였습니다.
6. 수정: 전진이 확인된 경우 이번 세션 시작 이후의 실제 저장 이력을 읽어 결과 map을 ID별로 복원합니다. 오래된 외부 기록은 새 평가로 세지 않으며, 취소/재평가 기준을 새로 만들지 않습니다. 평가·예약을 다시 계산하거나 이력을 합산하지 않습니다.
7. 수정 전 회귀 검사에서 resume/workspace **2개 실패**를 확보했습니다. 수정 후 관련 183개 검사 통과, 전체 **75개 파일·1,309개 통과, 실패·생략 0**, 타입 검사·프로덕션 빌드 통과.
8. 정확한 1.3.9 로드 후 같은 실패·복구·이어하기를 실제 UI로 반복했습니다. **완료: 전체 1·암기 1**, 변경 ID 1개·이력 증가 1. `69-*`, `70-*`, **`71-fixed-recovery-result-*`**가 수정 후 증거입니다. 재실행 뒤 다른 정상 세션의 완료도 2문제·암기 1·너무 쉬움 1로 일치했습니다.

[study-session.test.js](../../../tests/study-session.test.js)에 resume/workspace 복원과 세션 이전 기록 제외를 추가했습니다. 자동 검사만으로 실제 앱 결과를 대신하지 않았습니다. FSRS·저장 구조·동기화 선택 정책은 변경하지 않았습니다.

추가로 재현이 확정된 미수정 제품 결함은 없습니다. 아래 도구·환경 제한을 제품 정상의 무제한 보증으로 해석하지 않습니다.

## 화면·저장 데이터 대조

- 최초 네 평가: 표시 **1분·2분·2일·2시간**과 `card.due - last_review`가 각각 **1·2·2880·120분**으로 정확히 일치했습니다. 이후 실제 1/2분 기한 도래 반복도 이력에 구분됩니다. 반복 출제를 중복 클릭으로 판단하지 않았습니다.
- 이동·삭제·관련 문제 이동만으로 다른 문제의 평가를 바꾸지 않았습니다. 이동 실패 재시도 뒤 이전 과목 요약에서 항목이 사라지고 대상에 한 ID만 남았습니다. 1.3.8 감사에서 남았던 마지막 인덱스 복구 경로도 이번 실제 앱에서 확인했습니다.
- 플러그인 재로드·보관함 창 재실행 전후 `reviews`와 `settings`가 동일하고 queue·seed·index·mode·answerVisible·sessionSummary도 같았습니다. 큰 글자·나란히 보기·무작위 순서도 유지됐습니다.
- 실제 UI 조작으로 신규/학습/재학습/미래 복습을 만들었습니다. 기한 도래 분기를 빠르게 확인하기 위해 KCL·자기 선속·RC의 **due만 과거로 이동한 준비물**은 `artificial-due-fixture.json`, `69-*`, `82-related-fixture.json`에 분리합니다. 이 준비물을 실제 경과 시간/평가로 만든 기록이라고 주장하지 않습니다.
- Word ZIP/CRC·document.xml을 읽어 세 질문과 편집 문장·표·LaTeX를 대조하고 PNG 미디어를 확인했습니다. SVG 제외와 수식 원문 출력은 화면에서 명시된 동작이며 조용한 손상으로 판단하지 않았습니다.

## 도구 장애와 정상 재실행의 구분

전면 앱이 Codex로 전환되는 것을 OS 진단으로 확인했습니다. 오래된 AX/캡처와 `elementHasNoFrame`·`noWindowsAvailable`은 제품 오류로 세지 않았습니다. 현재 창 재선택·메뉴 취소·짧게 전면 유지한 뒤, 실제 renderer DOM과 Electron 캡처를 병행해 진행했습니다. 앞선 캡처 전체를 통과 증거로 채택하지 않고 아래 최종 자료를 우선합니다.

자동화의 CSS 모달 선택/닫기 위치 오류와 콘솔 문자열 입력 오류도 별도로 발생했습니다. 실제 DOM 구조를 다시 읽어 수정했으며, 이 오류 로그는 MIA 제품 예외가 아닙니다. 새 Obsidian의 실제 닫기 제어는 `modal-header-button`이었습니다.

검증 중 runtime 플러그인 관리 API로 켜진 상태와 디스크 활성화 목록이 다를 수 있음을 확인했습니다. 초기 창 재개 때 목록이 비어 있던 상태는 통과로 처리하지 않았습니다. 시작 진단에 1.3.9 `loaded`가 있고 `failed`가 없었으며, 정상 `enablePluginAndSave` 완료 후 enabled set과 디스크에 `mia-study`가 포함된 것을 확인했습니다. 그 상태로 다시 연 창은 별도 수동 활성화 없이 1.3.9와 시험 2/2를 복원했습니다. 초기 UI 스위치 변경이 저장되지 않은 세부 원인은 이 자료만으로 확정하지 않습니다. MIA가 활성화 목록을 지웠다는 근거는 없습니다.

이 과정에서 사용자 앱 전체를 강제 종료하거나 권한·계정·동기화 설정을 변경하지 않았습니다. 전면 유지용 두 진단 작업도 종료됐고, 일회성 실패 주입은 모두 원래 함수로 복구했습니다.
