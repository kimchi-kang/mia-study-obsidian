# 문제 편집 검증 — 2026-10-27

## 변경

- 연습(암기)·시험 문제 영역에 `문제 편집` 버튼 추가. 저장된 문제 ID로 현재 항목을 찾는다.
- 기존 문제 목록 상단에 대상 ID의 항목을 강조 표시하고 기존 수정창을 즉시 연다. 검색·필터·정렬을 변경하지 않고 대상만 별도로 노출한다.
- 저장·취소·창 닫기 후 진행하던 세션으로 복귀한다. 문제 ID 순서·현재 위치·답 공개 상태·평가·시작 시각을 보존한다.
- 원본 Markdown 저장과 인덱스 갱신은 기존 기능을 사용한다. 세션은 ID 목록만 보관하므로 복귀 시 새 인덱스의 질문·정답을 즉시 표시한다.
- 기존 FSRS 평가는 수정하지 않는다. 평가한 문제의 정답이 바뀌면 자동 재채점하지 않는다는 안내와 직접 재평가 안내를 표시한다.
- 원본 삭제 시 위치를 유지하고 안내한다. 저장 실패 시 초안을 보존하고 재시도한다. 저장 중에는 취소로 닫히지 않는다.
- 원본 저장 뒤 파생 노트 갱신이 실패한 경우 부분 저장 상태를 명시하고, 저장된 원본의 비교 기준을 갱신해 재시도 시 충돌하지 않게 한다.

## 검증

- 실제 Obsidian 1.14.5의 별도 `MIA-Native-Flow-QA` 보관함에서 두 모드 모두 문제 표시 → 문제 편집 → 기존 수정창 → 질문·답변 저장 → 같은 세션 복귀를 수행했다.
- 시험은 1/3 위치와 정답 숨김 상태를 유지했다. 정답 보기 후 수정한 답변을 표시했다.
- 연습은 2/3 위치를 유지하고 수정한 질문·답변을 즉시 표시했다.
- 실제 문제은행을 다시 읽어 두 수정의 질문·답변 및 세 개의 고유 ID 보존, 다른 동일 질문 항목의 답변 보존을 확인했다.
- 최종 빌드를 기존 브라우저 실행 환경(Obsidian 외부 경계만 대체)에서도 확인했다. 344px 연습 편집 왕복과 ID 지정, 순서·인덱스·세션 시작 시각 보존을 확인했다. 실패 시 초안 미저장·오류 표시, 재저장, 취소도 확인했다.
- 다른 과목 필터 및 수정일 정렬을 유지한 상태에서 대상 ID를 별도 노출하는 것을 확인했다. 원본 삭제 시 자동으로 다음 문제로 넘어가지 않았다.
- 344×740, 390×844, 768×900 화면에서 편집 버튼이 가로 화면 안에 있고 평가 조작 영역과 겹치지 않음을 확인했다. 최종 빌드 시험 저장 뒤 정답 숨김도 재확인했다.
- `npm test`: 69개 파일, 1,132개 테스트 통과. 기존 조건부 테스트 2개 제외. 이번 기능의 회귀 테스트 14개 추가.
- `npm run build`: TypeScript 검사와 프로덕션 빌드 통과. `git diff --check` 통과. 별도 lint 스크립트는 없다.

## 설치와 제약

- 사용 중인 `다용도 보관함`의 플러그인 파일 3개를 백업하고 최종 빌드로 설치했다. 파일 일치를 검증했다. data.json·ui-state.json은 설치 전후 동일했다.
- 최초 업데이트 로드에만 Obsidian 새로고침 또는 플러그인 재로드가 한 번 필요하다. 진행 중인 개인 세션을 강제로 재로드하지 않았다. 새 기능 안에서 편집할 때는 재시작하지 않는다.
- 모바일·폴드의 실제 Android/iOS 기기는 사용하지 않았다. 화면 크기 재현 검증이다.
- 기존에 있던 관련 없는 작업 변경은 보존했다. GitHub 푸시·공개 배포는 수행하지 않았다.
- 원본과 파생 노트 전체를 하나의 파일시스템 트랜잭션으로 묶지는 않는다. 부분 갱신 실패 시 원본 저장 여부를 정확히 알리고 초안을 유지해 재시도하게 한다.
