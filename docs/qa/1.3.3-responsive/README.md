# 1.3.3 소스 반응형 보강 · 2026-10-26

이 기록은 main 소스 및 로컬 설치의 1.3.3 추가 수정에 해당합니다. 최신 정식 릴리스 1.0.3의 다운로드에는 포함되지 않습니다.

## 변경

- 좁은 설정창에서 간격 입력·단위·삭제 버튼이 잘리던 문제를 편집기 너비 기준 재배치로 수정했습니다. 내부 너비 220px 이하에서는 삭제 버튼을 다음 줄로 두며, 더 좁아지면 입력과 단위도 한 열로 표시합니다.
- 좁은 학습 화면에서 다섯 탭을 한 줄로 강제하던 규칙을 바꿔 최소 열 너비에 따라 재배치합니다.
- MIA 팝업 닫기 버튼에 최소 44×44px 조작 영역을 확보했습니다.
- 문제·답안·평가 기능 및 기존 저장 형식은 유지합니다.

## 검증

| 순서 | 범위 | 결과 |
| --- | --- | --- |
| 1 | 280×740 홈·시험·정답·평가, 긴 한영 문구·큰 UI 글자 | 줄바꿈·탭 재배치 및 네 평가 버튼 확인 |
| 2 | 학습 화면 260~1460px, 10px 간격 121개 너비 | 검사한 버튼·입력창의 가로 경계 이탈·내부 넘침·44px 미만 조작 영역 없음 |
| 3 | 설정창 280/320/350/354/355/356/357/360/393/480/481/690/768/1024/1440px | 단계 행 가로 넘침 없음, 내부 219/220/221px 경계 및 닫기 44×44px 확인 |

| 10 | 최종 스타일 후 관련 자동 검사 | 3개 파일·20개 통과 |

모든 크기는 물리 해상도가 아닌 CSS 논리 viewport px입니다. 393×852는 iPhone 16급, 280/344px와 690px는 폴드 커버/내부 화면 비율을 대표하는 모의 검사값이며 특정 모델의 실측값이 아닙니다. 기존 호스트는 상단 검증 도구 40px와 모바일 앱 하단 여유를 예약하므로 실제 MIA 패널은 더 작습니다. 도구 막대 자체는 제품 검사에서 제외했습니다.

추출한 Obsidian CSS·배포 bundle과 합성 문제 및 저장소를 사용했습니다. 실제 iPhone/Galaxy Fold/iPad, iOS/Android WebView, OS 키보드 이동, 물리 터치·노치·힌지, 네이티브 선택창 위치는 직접 검증하지 않았습니다. 안전 영역은 CSS 변수, 키보드는 포커스 상태의 viewport 높이 감소로 모의했습니다. 모든 화면과 크기의 조합을 전수 검사한 것은 아닙니다.
