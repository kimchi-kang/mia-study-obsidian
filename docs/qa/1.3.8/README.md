## 발견·수정한 결함

### 1. 답변 편집이 공유 키워드 의미를 손상하거나 외부 갱신을 덮어씀

- 재현: 여러 줄 의미를 가진 키워드가 연결된 질문에서 답변만 바꿔 저장합니다. 또는 편집창을 연 뒤 다른 경로에서 의미를 바꾸거나, 의미 입력은 그대로 두고 키워드 순서만 바꿉니다.
- 기대: 수정하지 않은 의미는 대상 노트에 그대로 남아야 합니다.
- 기존 실제 동작: 의미 전체를 줄 단위 배열로 다시 나눠 모두 저장해 첫 의미가 잘리고 다음 키워드에 앞 키워드의 다음 줄이 들어갔습니다. 오래된 입력값으로 외부 변경을 덮어쓸 수도 있었습니다. 단일 키워드의 명시적 여러 줄 수정도 첫 줄만 저장했습니다.
- 원인·수정: [질문 편집 폼](../../../src/ui/manage-modals.ts)의 평탄화된 입력을 무조건 저장하던 경로를 수정했습니다. 변경하지 않은 의미는 쓰지 않고 대상별 원래 의미를 보존합니다. 한 키워드는 전체 줄을 저장하며 여러 키워드에서 넘치는 줄은 오류로 남겨 조용히 버리지 않습니다. 새로 연결한 기존 키워드의 빈 의미는 보존하고 기존 의미를 명시적으로 비우는 동작은 유지합니다.
- 검증: 다중 줄·외부 변경·순서 변경·보조 키워드·명시적 비우기 회귀 검사 통과. 실제 Obsidian에서 합성 답변만 수정·저장·재열기 후 코드 블록을 포함한 키워드 노트가 바이트 동일함을 확인했습니다.

### 2. 새 질문의 일부 저장 뒤 재시도하면 같은 질문이 중복 생성됨

- 재현: 문제은행 원본 저장은 성공했지만 과목 요약 노트 갱신이 실패한 상태에서 같은 편집창의 저장을 다시 누릅니다.
- 기대: 이미 저장한 ID를 유지해 후속 처리를 재시도해야 합니다.
- 기존 실제 동작: 편집창이 계속 새 질문 상태여서 새로운 ID의 질문을 하나 더 만들었습니다.
- 원인·수정: [생성·편집 진입점](../../../src/main.ts)이 원본 커밋 직후 저장된 ID와 스냅샷을 편집창에 전달합니다. 후속 실패 후에는 같은 ID의 수정으로 재시도합니다. 저장 어댑터가 커밋 후 오류를 반환하면 정확한 내용 재읽기로 저장 여부를 확인합니다.
- 검증: 프로덕션 저장 메서드와 편집창 진입점 회귀 검사 통과. 기존 격리 앱에서 과목 요약 노트만 일시적으로 읽기 전용으로 만들고 원본 저장 → 오류·입력 유지 → 권한 복구 → 재시도를 실행했습니다. 목록은 70→71이며 최종 합성 질문 ID는 한 개입니다.

### 3. 과목 이동의 일부 저장 후 재시도가 막히고 이전 과목 요약이 남음

- 재현: 대상 문제은행 삽입과 원본 삭제는 성공했지만 뒤의 인덱스/과목 요약 갱신이 실패합니다.
- 기대: 이동한 ID·경로와 상대 이미지 링크를 유지하면서 양쪽 과목 요약까지 복구해야 합니다.
- 기존 실제 동작: 편집창은 이동 전 경로를 사용해 재시도 시 원본 문제를 찾지 못했습니다. 이번 조사 중 경로만 보완한 중간 빌드에서도 이전 과목 요약 재시도가 빠지는 인접 결함을 추가로 확인했습니다.
- 원인·수정: [이동·재시도 경로](../../../src/main.ts)가 커밋된 대상 스냅샷을 전달하고 원래 입력의 상대 링크 기준 경로를 유지합니다. 이동 뒤 실패한 이전 과목을 기억해 원본 인덱스를 먼저 갱신하고 과목 요약도 최신 문제은행에서 다시 읽어 갱신하며, 이 작업도 완료되어야 편집창이 닫힙니다. 재실패하면 다음 저장에서도 갱신을 다시 시도합니다.
- 검증: 이동 후 실패·같은 ID 재시도·상대 이미지 대상 보존·이전 과목 요약 재실패 회귀 검사 통과. 이전 과목 요약 재시도를 보완한 1.3.8 빌드를 실제 격리 앱에서 정상 재로드하고, 합성 질문을 이동하면서 이전 과목 요약의 쓰기를 실패시켰습니다. 권한 복구 후 같은 편집창으로 재시도해 문제 하나·양쪽 요약 정합성·키워드 바이트 보존을 확인했습니다.

### 4. 키워드 의미의 코드 속 제목을 관리 구역 경계로 오인함

- 재현: 의미에 fenced 코드 블록 안의 `## 제목` 또는 네 칸 들여쓴 제목 예시를 넣고 다시 읽거나 수정합니다. 반대로 실제 제목에 1~3칸을 들여쓰거나 코드 블록을 닫지 않는 입력도 확인했습니다.
- 기대: 코드 예시 전체를 의미로 취급하고 뒤의 연결 구역을 보존해야 합니다. 실제 관리 구역을 분리하거나 삼키는 입력은 저장 전에 막아야 합니다.
- 기존 실제 동작: 검증기는 fenced 제목을 허용했지만 읽기·교체는 제목으로 오인해 의미를 잘랐고 교체 뒤 코드 잔재를 남겼습니다. 정상 노트를 병합 불가로 판정할 수도 있었습니다. 들여쓴 실제 제목과 미종결 fence는 관리 구역을 손상할 수 있었습니다.
- 원인·수정: [키워드 의미 처리](../../../src/core/keyword-note.ts)의 읽기·수정·병합 검사에 같은 코드 블록 인식 경계를 사용합니다. [제목 검사](../../../src/core/markdown-structure.ts)는 실제 Markdown 제목의 0~3칸 들여쓰기를 인식하고 미종결 fence를 거부합니다.
- 검증: fenced 제목 왕복·전체 교체·연결 보존·들여쓴 코드·실제 구역 주입·미종결 backtick/tilde 회귀 검사 통과. 실제 질문 편집창에서 전체 코드 의미 표시와 답변만 편집한 뒤 원문 보존을 확인했습니다. 키워드 병합 자체를 이번 실제 앱에서 실행한 것은 아닙니다.

## 검사와 실제 앱 증거

## 조사 범위와 남은 불확실성

문제 생성·수정·이동과 파생 노트, 키워드 저장·병합, 파일 묶음 쓰기와 롤백, data-store 재시도·병합, 이어하기 쓰기 순서, 세션 편집·평가 잠금·이동·취소·타이머, FSRS/출제 계산의 관련 구현과 기존 회귀 검사를 검토했습니다. 위험도가 높은 원본 커밋과 후속 처리 실패의 경계를 우선 재현했습니다.

추가로 재현이 확정된 미수정 결함은 남기지 않았습니다. 마지막 인덱스 실패 복구 보완분은 자동 회귀 검사를 통과했으나 제어 연결 장애로 실제 앱 재검증이 남습니다. 다음을 완료로 간주하지 않습니다.

- 모든 과목·키워드 이름 변경/삭제의 실제 앱 조합, 모든 외부 동시 변경·앱 종료·재시도 조합. 이번 실제 앱 범위는 위 합성 생성·편집·이동·저장 실패입니다. 커밋 여부 재읽기 자체가 실패하는 경우의 원자성까지 보장하지 않습니다.
- 날짜를 넘긴 실제 장시간 학습, 모든 일일 상한 조합, 대량 문제의 실제 성능 측정, 반복 열기·닫기의 메모리 프로파일링. 관련 자동 검사는 통과했으나 이번에 실측으로 전부 재검증하지 않았습니다.
- 모바일 실기기·OS 키보드·실제 두 기기 클라우드 전달·오프라인 재연결. 기존 미검증 상태를 유지합니다. 로컬 파일 모형 검사를 실기기 통과로 사용하지 않습니다.

FSRS 단계·학습일 경계·출제량/통계 정의·설정 우선순위는 관련 정책과 구분했으며 근거 없이 결함으로 변경하지 않았습니다. 학습 알고리즘·영속 형식·동기화 선택 정책은 변경하지 않았습니다.

## 반영과 보존

소스의 코드 4개·회귀 검사 4개, 버전 파일 4개, 빌드 `main.js`, 변경 내역·상태·검증 문서를 함께 로컬 커밋합니다. CSS는 변경하지 않았습니다. 최종 격리 설치의 `main.js`·`styles.css`·`manifest.json`은 빌드와 바이트 동일합니다.

사용자 플러그인 폴더의 시작 시점 파일 7개는 최종에도 전부 동일합니다(설치 세 파일·data.json·ui-state.json 포함). 이는 보관함 전체 736개를 이번에 새로 비교했다는 뜻이 아닙니다. 격리의 data.json도 시작 전과 동일합니다. 합성 질문·키워드와 캡처·백업은 격리 경로에 보존했습니다. **사용자 설치 갱신·원격 푸시·태그·공개 릴리스는 하지 않았습니다.**
